# Cache Utility: концепция и методология

Проект оценивает гранаты по наблюдаемому эффекту и геометрии карты. Он различает записанный урон/ослепление, прогноз модели и расчёт перекрытия линий обзора смоком. Несопоставимые величины не складываются в общий рейтинг.

## Термины

| Термин | Значение в проекте |
|---|---|
| Бросок | Одно событие применения гранаты; одна строка исходной таблицы |
| Раскидка | Способ броска гранаты из определённой точки с заданным направлением/движением; не отдельная целевая метка |
| Точка броска | Записанное положение игрока при броске |
| Точка детонации | Записанная конечная позиция гранаты; для смока задаёт положение предполагаемого объёма дыма |
| Смок | Дымовая граната (`Smokes`) |
| Флешка | Световая граната (`Flashbangs`) |
| HE | Осколочная граната (`HEs`) |
| Молотов / зажигательная граната | Два игровых типа, объединённые источником в `Fires`; далее рассматриваются вместе |
| T / CT | Сторона террористов / контртеррористов |
| Противник / союзник | Игрок другой / той же команды относительно бросающего |
| Линия обзора | Отрезок между позицией наблюдателя и целью, проверенный на пересечение со стенами |
| Зарегистрированный эффект | Урон или добавленная величина ослепления, явно записанные в источнике |
| Тактический импакт | Вклад в исход раунда; непосредственно в исходнике не измерен |

Технические термины train, test, CV и OOF относятся к обучению: train — обучающие матчи; test — отложенные; CV — перекрёстная проверка; OOF — прогноз для части train моделью, не обучавшейся на этой части.

## Данные и пропуски

Одна строка — один бросок. Из 10 000 исходных матчей 9 984 содержат гранаты, 16 пусты. Сохранены все 2 385 417 бросков.

| Граната | Бросков | Известных исходов | Положительных исходов |
|---|---:|---:|---:|
| Смок | 729 947 | Не задано | Не задано |
| Флешка | 643 914 | 518 976 | 332 083 |
| HE | 565 392 | 216 234 | 207 380 |
| Молотов / зажигательная | 446 164 | 60 115 | 60 115 |

`null` означает отсутствие достоверного исхода, а не промах. Доля известных исходов показывается отдельно для каждого типа. У флешек она 80,6%; наличие метки само предсказывается на test с ROC-AUC 0,690. Без предположений о пропусках доля положительных флешек среди всех ограничена широким диапазоном 0,516–0,710.

`StartProperVelocity` во всех бросках равен отрицательной скорости игрока. Он не используется как скорость полёта гранаты. `GeneralInfo.PosFrom` — первая записанная позиция гранаты; точная сила броска и начальная скорость снаряда по этому полю не установлены. Постматчевый рейтинг не используется как независимая оценка игрока до броска.

## HE и Молотов / зажигательная

Наблюдаемая величина — записанный HP-урон противникам, отдельно от урона союзникам и себе. Сумма учитывает только зарегистрированные значения и показывается с покрытием данных. У огненных гранат нет известных отрицательных примеров, поэтому классификатор успешности по доступным меткам не строится.

XY-площадь финального контура есть только у 1 875 бросков. Это проекция записанного контура, а не время контроля зоны или площадь ожога с учётом стен и высоты. Векторизация карты не восстанавливает урон без положения целей, времени, брони и механики игры.

## Флешка: ослепление и его величина

Модель классифицирует зарегистрированный эффект флешки, а не тип гранаты. `impact=1` означает положительное добавление ослепления противнику; `0` — известный нулевой эффект; `null` — неизвестный исход. Частичное ослепление также может дать положительную метку: она не означает полного ослепления или невозможности стрелять.

Количество ослеплённых противников — разные PlayerID с положительным добавлением, без повторного счёта внутри гранаты. Союзники и сам бросающий учитываются отдельно.

Вероятность положительного эффекта `p` и условное среднее эффекта `m` оцениваются раздельно. Ожидаемая записанная величина — `p × m`. Аналогично оценивается ожидаемое количество ослеплённых. Положительное условное среднее количества ограничено диапазоном 1–5.

Есть два набора входа. `setup` — состояние бросающего: позиция, взгляд, скорость, приседание/прыжок, сторона и индекс раунда. `release` добавляет смещение первой позиции гранаты и предыдущие броски сторон в текущем раунде. События одного тика не попадают друг другу в историю. Конечная точка, эффект, победа и выживание не становятся признаками. Полная история противника может быть доступна наблюдателю, но недоступна игроку в живом матче.

## Проверка модели

Все броски одного матча находятся в одной части. Выбор конфигурации и обоих порогов использует пять CV-разбиений только train. Сравниваются логистическая регрессия, дерево решений, HistGradientBoosting, CatBoost и приближённая RBF-модель; отдельный CatBoost служит сравнением с входом `setup`. Выбор — минимум совокупного OOF log loss среди зафиксированных конфигураций, а не глобальный оптимум алгоритмов.

Выбран HistGradientBoosting с контекстом броска. Test: 104 238 известных исходов из 1 994 матчей.

| Метрика | Оценка | 95% интервал по матчам |
|---|---:|---:|
| ROC-AUC | 0,7427 | 0,7395–0,7461 |
| Balanced accuracy | 0,6723 | 0,6693–0,6756 |
| Accuracy при пороге по balanced accuracy | 0,6786 | 0,6753–0,6822 |
| Brier | 0,1903 | 0,1889–0,1916 |
| Log loss | 0,5601 | 0,5568–0,5631 |

При пороге 0,5 accuracy = 0,7062, balanced accuracy = 0,6359. Строгий положительный порог даёт precision 0,8028 при охвате 0,4854 и recall 0,6084. Интервал precision 0,7993–0,8063: гарантии 80% на будущих данных нет. Порог и охват необходимо оценивать вместе.

Сравнение HGB одинаковой сложности показывает вклад контекста: ROC-AUC 0,7264 → 0,7427. Прежний `setup` CatBoost на тех же отложенных матчах даёт 0,7173. Это сравнение входов/конфигураций, а не доказательство превосходства одного семейства моделей вообще.

Рабочие модели дообучены на всех известных исходах после выбора. Для проверки сохранены отдельные модели. В показателях известных train-строк используются OOF-прогнозы всех трёх моделей; test — отложенные прогнозы. Unknown-прогноз не подменяет unknown-метку.

Интервалы построены по 300 пересэмплированиям целых test-матчей. Holdout уже изучался на предыдущих этапах, поэтому новой независимой проверкой не является. Интервалы отражают вариацию между матчами, но не исправляют пропуски, повторное изучение test и смену сборки игры.

## Смок: геометрическое перекрытие линий обзора

Для исходного набора оценивается доля локальных свободных от стен линий, пересекающих предполагаемый объём дыма. Точки взяты из navmesh на предполагаемой высоте глаз. База: радиус XY 144, Z 96, центр на 72 выше точки детонации, минимальная хорда 32 и локальный радиус 450 единиц.

При нулевом знаменателе результат неизвестен. Массовый расчёт округляет координаты к 16 единициам; расчёт одного смока использует точные координаты. Радиусы 96/144/192 — сценарии чувствительности, не доверительные границы.

При наличии синхронной демо рассчитывается время геометрического перекрытия обзора противника, суммируемое по направленным парам «наблюдатель — цель». Учитываются живые игроки, направление взгляда, стены, время жизни и наложение смоков. Перекрытие каждого смока отдельно и дополнительное перекрытие при других смоках разделены. Большие пропуски сэмплов не интегрируются.

Форма/плотность дыма, рост, отверстия от пуль/HE, динамические двери и визуальное обнаружение не калиброваны по игровому изображению. Соответствующих исходным Cache-матчам демо нет. `actual_enemy_view_blocked` остаётся `null`. Проверка импорта Mirage не является проверкой смоков Cache. Дым может закрывать и союзников, поэтому большая доля перекрытых линий сама по себе не устанавливает пользу команде.

## Показатели игроков и границы выводов

У игрока раздельно показаны HP, количество ослеплённых противников, сумма FlashDurationAdded, геометрическое перекрытие смоками и покрытие исходов. Отклонение флешек от модели — среднее `(наблюдаемый факт − OOF/test вероятность)` среди известных исходов. Это модельное сравнение при данном составе бросков, не независимый рейтинг навыка и не причинный вклад.

Для интервала отклонения нужны ≥50 известных флешек, ≥5 матчей и ≤50% наблюдений из одного матча. Критерий проходят только 34 из 89 052 игроков; для остальных интервал не рассчитывается. Выживание и победа берутся только из фактических событий демо.

Связь гранат с победой или выживанием не устанавливает причинный импакт: бросок и исход зависят от общей ситуации раунда. Для проверки переноса нужен новый заранее отложенный набор Cache-демо с известной сборкой; для фактической видимости — синхронная телеметрия и проверка по записи игрового изображения.
