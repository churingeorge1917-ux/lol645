# Cache Utility: техническое описание

Анализ бросков гранат на Cache. Архив распаковывается в новую пустую папку. Единственная команда входа — `python scope.py`; исходный код находится в пакете `scope_cache`. В поставку входят подготовленные данные, обученная модель и выполненный ноутбук. Методология и значения терминов описаны в [README_CONCEPT.md](README_CONCEPT.md).

## Установка

Нужен **Python 3.12, 64 bit**. Версии библиотек закреплены в одном `pyproject.toml`. Команды PowerShell из папки проекта:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\python.exe scope.py doctor
.\.venv\Scripts\python.exe scope.py summary
.\.venv\Scripts\python.exe scope.py score --input tests/fixtures/grenades.json
```

После активации окружения используйте `python` вместо полного пути. Linux/macOS: `python3.12 -m venv .venv`, затем `.venv/bin/python`. Сохранённая модель проверяет версии scikit-learn/CatBoost и свои контрольные суммы до загрузки. Команды Windows подготовлены; исполнение проверяется на Linux/Python 3.12.

Дополнительные зависимости устанавливаются из того же файла:

```powershell
python -m pip install -e ".[notebook]"           # Ноутбук и Jupyter
python -m pip install -e ".[demo]"               # Чтение .dem
python -m pip install -e ".[dev,notebook,demo]"   # Все проверки и возможности
```

Для просмотра сохранённых графиков и прогноза по одной гранате не требуется обучение или первичный файл на 1,57 ГБ.

## Команды

Все команды запускаются из папки проекта. Полная справка: `python scope.py --help`, справка команды: `python scope.py demo --help`.

| Команда | Действие |
|---|---|
| `python scope.py doctor` | Версии Python/библиотек и наличие подготовленных данных |
| `python scope.py summary` | Сохранённое качество модели флешек и ограничения |
| `python scope.py score --input INPUT.json` | Оценка одной гранаты или списка |
| `python scope.py score --input INPUT.json --output OUTPUT.json` | Сохранение результата отдельно от входа |
| `python scope.py score --input INPUT.json --mode setup` | Прогноз флешки только по состоянию бросающего |
| `python scope.py score --input INPUT.json --mode release` | Требует также контекст броска флешки |
| `python scope.py run` | Досборка отсутствующего, расчёт показателей игроков, аудит |
| `python scope.py run --rescore` | Пересчёт показателей всех гранат и игроков |
| `python scope.py run --source ORIGINAL.list` | Восстановление отсутствующих исходных таблиц |
| `python scope.py train` | Сравнение шести конфигураций, выбор по CV, обучение рабочих моделей |
| `python scope.py train --without-kernel` | Сравнение без RBF; это другой набор кандидатов |
| `python scope.py diagnostics` | Пересчёт интервалов, срезов, проверки пропусков и геометрии |
| `python scope.py audit` | Полная проверка данных, разбиений и сохранённых прогнозов |
| `python scope.py check` | Тесты исходного кода |
| `python scope.py report` | Выполнение и сохранение всех ячеек ноутбука |
| `python scope.py map --fetch` | Загрузка закреплённой сборки Cache и построение линий обзора |
| `python scope.py map` | Перестроение линий обзора из имеющихся map assets |
| `python scope.py pack --output ../Scope_Cache_PoC_fixed.zip` | Проверенный ZIP с готовыми данными |

`score` по умолчанию использует `auto`: при полном контексте флешки выбирает `release`, иначе `setup` и перечисляет отсутствующие признаки. Для HE и Молотова/зажигательной выводятся записанные показатели; для смока — геометрическое перекрытие. `run --retrain` повторяет обучение и обновляет зависимые расчёты. Ошибка приводит к ненулевому коду завершения.

## Таблицы данных

| Файл | Содержание |
|---|---|
| `data/events.parquet` | Все 2 385 417 бросков; исходные координаты, состояние бросающего, записанный эффект |
| `data/release_context.parquet` | Предыдущие броски в раунде, смещение первой позиции гранаты, число ослеплённых |
| `data/grenade_scores.parquet` | Наблюдения, прогнозы и геометрия отдельно; для неизвестного исхода метка остаётся `null` |
| `data/player_utility_profiles.parquet` | Раздельные показатели типов гранат, покрытие данных и отклонение флешек от прогноза модели |

Парные `.metadata.json` описывают происхождение и SHA256 конкретной входной/выходной таблицы. Это контроль целостности, а не дополнительная версия данных. Таблицы исходных бросков и контекста раздельны, чтобы сохранить проверенный первичный файл событий побайтно. Контекст связан строго по `source_row_index`; порядок и полнота проверяются.

Источник: `grenades_by_match_0726.list`, 1 566 906 554 байта, SHA256 `4edf4e909349d5131ac39a6d97a9bd49436772c939c7ade3d897713dca8ebe17`. В ZIP первичный файл не включён; полные подготовленные таблицы включены. Для Git крупные данные исключены; восстановление требует исходник с этой контрольной суммой. Матчи автоматически не скачиваются. Прошлая проверка повторного извлечения контекста с совпадающим SHA256 сохранена в его метаданных.

## Вход JSON

Готовый пример всех четырёх типов: `tests/fixtures/grenades.json`. Одна запись — один бросок. Идентификаторы передаются строками. Для новых прогнозов нужны только доступные признаки; наблюдаемый эффект можно опустить.

| Поля | Значение |
|---|---|
| `type` | `Smokes`, `Flashbangs`, `HEs`, `Fires` — обозначения типов в исходнике |
| `map_name` | Необязательное; если передано, требуется `de_cache` |
| `player_x/y/z` | Точка броска: положение игрока в мировых координатах |
| `view_dx/dy/dz` | Единичный вектор направления взгляда |
| `velocity_x/y/z` | Скорость игрока, не гранаты |
| `is_crouching`, `is_airborne` | Приседание / нахождение в воздухе, 0 или 1 |
| `side`, `round_index` | 2 = T, 3 = CT; индекс раунда источника |
| `release_offset_x/y/z` | Первая записанная позиция гранаты минус позиция игрока |
| `past_{smokes,flashbangs,hes,fires}_{own,opponent}` | Восемь счётчиков строго предыдущих бросков своей команды / противника |
| `past_player_throws` | Предыдущие броски этого игрока в текущем раунде |
| `ticks_since_first_grenade` | Тики от первого записанного броска раунда, не от начала раунда |
| `ticks_since_own_grenade`, `ticks_since_opponent_grenade` | Тики от предыдущего броска стороны, −1 при его отсутствии |
| `end_x/y/z` | Точка раскрытия смока. Не используется для прогноза ослепления |
| `impact` | Наблюдаемая метка: 0, 1 или `null`; не входной признак |

`setup` использует 13 признаков состояния бросающего. `release` добавляет 15 исходных и 5 вычисляемых признаков: скорость движения, горизонтальную скорость, dot взгляда/скорости, длину смещения и cosine взгляда/смещения. Одновременные броски одного тика не включают друг друга в прошлое. Пропуски контекста не заполняются нулями; `--mode release` при них возвращает ошибку.

`outcome_status` един для таблицы и JSON: `known_positive`, `known_zero`, `unknown`, `not_applicable_smoke`. Неприменимый к типу гранаты показатель остаётся `null`: HP не записывается как нулевой урон флешки, а ослепление — как нулевой эффект HE.

## Модель и сохранённая проверка

`models/flash.joblib` содержит отдельные модели для проверки и использования: классификатор ослепления, две условные регрессии и вариант `setup`. `models/flash.metadata.json` содержит признаки, кандидатов, метрики, ID train/test/CV, пороги, версии библиотек и SHA256.

`models/flash.validation.parquet` объединяет все известные исходы: основной OOF/отложенный прогноз, обе условные регрессии и ожидания, OOF каждого кандидата, сравнение с `setup` и проверку вклада контекста при одинаковой сложности HGB. Для кандидатов test-столбцы намеренно пусты: их не используют для выбора модели. Рабочая модель обучена на всех известных исходах; качество вычисляется по отдельным моделям проверки.

Основной HGB: 200 итераций, 31 лист, min_samples_leaf 100, L2 10, early_stopping=False. Выбор конфигурации — минимум совокупного OOF log loss по пяти разбиениям train-матчей. Оба порога также выбираются по train OOF. Условные регрессии Poisson HGB обучаются на положительных исходах. В таблице показателей все известные строки используют OOF/отложенные значения всех трёх прогнозов.

## Демо

```powershell
python scope.py demo --input MATCH.dem --output demo_context --match-id EXACT_MATCH_ID --expected-map de_cache
python scope.py demo --input MATCH.dem --output demo_context --match-id EXACT_MATCH_ID --expected-map de_cache --score-smokes
```

Входом также может быть CS-NET `cs2.demo.v2` JSON/JSON.gz. `--join-events` связывает результаты с исходными бросками Cache только при точном совпадении ID матча/игрока/раунда. `--round-offset` явно сдвигает нумерацию раундов. Имена и похожие координаты для сопоставления не используются.

SteamID64 по умолчанию остаётся точной строкой. `--id-scheme steam-account32` явно вычитает 76561197960265728 с проверкой диапазона; соответствие этой схемы PlayerID исходника требует проверки по соответствующей демо. Float-ID отклоняются. Данные записываются атомарно: ошибка не оставляет частичный импорт.

В `.dem` берутся сэмплы каждые 16 тиков и точная граница round_end. Последующие смерти не влияют на выживание. Записанный владелец и entity ID смока сохраняются, но entity ID не объявляется исходным custom ProjectileID. Высота глаз `64−18×duck_amount` — допущение, не измеренная позиция камеры. Поле зрения (FOV) в геометрическом расчёте по умолчанию принято равным 90°. Неизвестные состояния не подменяются выживанием.

Геометрия закреплена на CS2 client 2000934 / patch 1.41.9.1. При известном несовпадении патча расчёт смоков блокируется. `--allow-geometry-mismatch` допускает только явно помеченный эксперимент. Путь `.dem → таблицы` проверен на Mirage; это не проверка видимости на Cache. Сведения сохранены в `reports/analysis.json`.

## Проверки и отчёт

```powershell
python -m ruff check .
python scope.py check
python scope.py audit
python scope.py report
```

Тесты проверяют прошлый контекст, отсутствие утечки, неизменность выбора при подмене test-меток, входные признаки, геометрию, точность ID и границы раундов. Полный аудит воспроизводит метрики, проверяет все test-прогнозы, полноту таблиц, контрольные суммы и неизвестные исходы. Перемещение файлов не требует переобучения: матрица признаков, метки, разбиения и прогнозы сопоставляются с сохранёнными результатами.

Ноутбук открывается командой `python -m jupyterlab utility_analysis.ipynb`. При выполнении он проверяет контрольные суммы, использует те же определения показателей и сохраняет шесть графиков. Результаты прошлых проверок не подменяют текущий статус: он записан в `reports/checks.json`.

`pack` исключает временные файлы и окружение, проверяет CRC ZIP и SHA256 каждой записи. Внутри создаётся `MANIFEST.json`. Файлы joblib — доверенные поставляемые модели; произвольный внешний pickle/joblib не является поддерживаемым вводом.
